## Модули

| Модуль | Зона ответственности | Основные каталоги |
|---|---|---|
| M1. Ядро и платформа | config, logger, БД, миграции, middleware, docker, CI | `cmd/`, `internal/{config,logger,storage}`, корень репозитория |
| M2. Движок прохождения | сессии, ветвление, фиксация ответов | `internal/domain/branching.go`, `internal/service/{training,catalog}.go`, `internal/repository/{session,scenario}.go` |
| M3. Оценка и прогресс | скоринг, уровни, агрегаты, статистика | `internal/domain/scoring.go`, `internal/service/progress.go`, `internal/repository/progress.go` |
| M4. Аутентификация | регистрация, вход, токены | `internal/service/auth.go`, `internal/repository/user.go` |
| M5. Контент | сценарии, справочник, валидатор, загрузчик | `backend/seed/`, `internal/domain/validation.go`, `internal/service/content.go` |
| M6. Интерфейс | все экраны, интеграция с API | `frontend/` |

Правка чужого модуля согласуется в PR. Точки стыковки, зафиксированные в
день 1: `api/openapi.yaml`, `backend/seed/scenarios/scenario.schema.json`,
`backend/seed/risk_signals.json`.

## Архитектура

```
transport (HTTP) → service → repository → БД
                      ↓
                   domain (чистое ядро)
```

- Зависимости только вниз: репозиторий не вызывает сервис, сервис не
  принимает `http.Request`.
- `domain` не знает ни о БД, ни о HTTP. Оценка, ветвление и валидатор —
  чистые функции: на них набирается покрытие без поднятия контейнеров.
- Доменные структуры не сериализуются в ответ — только DTO из
  `internal/transport/http/dto`.

## Контракт API

`api/openapi.yaml` — источник истины.

1. Изменение API начинается с правки спецификации.
2. Спецификация, DTO и обработчик едут в одном PR.
3. Фронтенд генерирует типы: `make api-types`, руками их не правит.
4. Нереализованный эндпоинт отвечает `501` — это состояние каркаса.
   К защите таких ответов быть не должно.

## Код

- `gofmt` и `goimports` обязательны, импорты проекта — отдельной группой.
- Ошибки оборачиваются с контекстом, сравниваются через `errors.Is`/`As`.
- Доменные ошибки — в `internal/domain/errors.go`, перевод в коды ответа —
  в `transport/http/response.go`. Новый код сначала появляется в OpenAPI.
- Комментарий объясняет причину, а не пересказывает код. Ссылка на
  требование (FR13, SEC2) в спорном месте экономит ревью.
- `//nolint` — только с объяснением.

## Тесты

- Пишутся в той же задаче, что и код. Порог MNT5 — 60%, основной вклад дают
  M2 и M3.
- Таблицы кейсов для `Evaluate`, `ValidateScenario` и `ResolveNext` уже
  написаны и помечены `t.Skip` — реализуя функцию, снимите skip.
- Транспорту хватает тестов контракта: коды ответов, форма ошибки,
  разграничение публичных и защищённых маршрутов. БД для них не нужна.

## Безопасность

Проверяется на ревью: пароли только bcrypt-хешем и не в логах; чужой ресурс —
`404`, а не `403`; валидация на сервере; параметризованные запросы; секреты
из окружения; клиенту не уходят стек и текст SQL; в контенте нет рабочих
ссылок наружу.

## Git

- Ветки: `main`, интеграционная `develop`, работа — `feature/m3-scoring`.
- Коммиты в повелительном наклонении: «добавить расчёт уровня безопасности».
- PR в `develop`, слияние с зелёным CI. Перед PR: `make lint && make test`.

## Состояние каркаса

Незакрытые места помечены `TODO(<модуль>)`:

```bash
grep -rn "TODO(M" backend/
```

Заглушка возвращает `domain.ErrNotImplemented`. Реализуя метод, удаляйте
`TODO` вместе с заглушкой: оставшийся `ErrNotImplemented` — признак
незакрытой задачи.
